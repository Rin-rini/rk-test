# Гайдлайн: сборка дашборда из UI kit

Документ для разработчика: как **вручную** собрать аналитический экран из готовых частей репозитория, без своих «мини-компонентов» и разовых цветов.

**Где смотреть перед вёрсткой**

- **Storybook** (`npm run storybook`) — как выглядят и ведут себя контролы и графики: разделы *Foundation/Tokens*, *UI/Базовые*, *UI/Аналитика*, *UI/Типы графиков*.
- **Пример целого экрана** — `dashboard/components/BudgetDashboard.tsx`: шапка, фильтры, KPI, сетка графиков, таблица.

**Генерация экрана с помощью AI** описана отдельно в `AI_RULES.md`

---

## Что входит в UI kit

| Часть | Путь | Зачем |
| --- | --- | --- |
| Токены (цвета, шрифты, отступы, сетка) | `ui-kit/tokens/` | Единый внешний вид; подключаются через `ui-kit/tokens/index.css` |
| Компоненты | `ui-kit/components/ui/` | Кнопки, фильтры, KPI, таблицы, графики — импорт из `@ui-kit/components/ui/index.ts` |
| Раскладка экрана | `ui-kit/layout/` | 12-колоночная сетка, шапка: `@ui-kit/layout/index.ts` |
| Форматирование чисел | `ui-kit/visualization/` | `formatByMetric`, форматы для таблиц и осей графиков |
| Цвета серий графиков | `ui-kit/tokens/chartColors.ts` + `colors.css` | Палитра `--chart-*`, план/факт |


---

## Как выглядит экран

- **Тёмная тема:** фоны `--bg-app`, `--bg-panel`, `--bg-card`; текст `--text-primary` / `--text-secondary`.
- **Графики** — спокойные `--chart-blue`, `--chart-green`, …
- **План и факт** (и любые две серии): в kit задаёте проп `series` у графика — `key`, `name`, опционально `color`.
- **Отклонения:** `--status-success`, `--status-warning`, `--status-critical`.
- **Подписи интерфейса — на русском.**

Все цвета и размеры нужно брать как переменные из токенов.

## Скелет страницы (порядок блоков)

Импорт раскладки:

```ts
import { DashboardPage, DashboardPageHeader, dashboardGrid } from '@ui-kit/layout/index.ts'
```

Сверху вниз:

1. **Контейнер** — корень экрана в `DashboardPage` (`<main>`, сетка `dashboardGrid.page`, анимация появления из kit).
2. **Шапка** — `DashboardPageHeader` (заголовок, при необходимости `lead`, список `notes`, кнопки в `actions`).
3. **Фильтры** — `FilterPanel` (по умолчанию горизонтальная строка). Период — через встроенный `DateRangePicker` (два клика по датам, пресеты `DATE_RANGE_PRESETS`).
4. **KPI** — секция с `dashboardGrid.kpiRow`, внутри только `KPICard` (обычно 4 штуки в ряд).
5. **Графики** — секция `dashboardGrid.charts`, каждый график в `ChartCard` + класс ширины (см. ниже).
6. **Таблица** — `DataTable`; при длинном списке включайте `scrollable`.

**Ширина карточек графика** — класс на `ChartCard`:

| Класс | Колонок из 12 | Смысл |
| --- | --- | --- |
| `chartFull` | 12 | одна широкая карточка |
| `chartWide` / `chartNarrow` | 7 / 5 | пара в одном ряду |
| `chartHalf` | 6 | два равных блока в одном ряду |

Высоту графика задаёте пропом `height` у компонента графика, не через layout. 

**Фильтры слева:** `FilterPanel` с `layout="vertical"`, обёртка `bodyWithSidebar`, фильтры в `sidebar`, контент в `main`.

Состояние загрузки, отсутствия данных и ошибка передаются в KPI и графики статусом: `status` = `loading` | `empty` | `error` | `ready` (см. `DataStatus` в kit).

## Компоненты — краткий справочник

**Базовые:** `Button`, `Input`, `Select`, `Badge`, `Tooltip`, `Skeleton`.

**Аналитика:**

- `FilterPanel` — конфиг полей: период, мультивыбор, одиночный список.
- `KPICard` — значение, `unit` (`currency`, `percent`, …), опционально тренд.
- `ChartCard` — заголовок + слот для графика + скелетон/пусто/ошибка.
- `DataTable` — колонки, сортировка, фильтры по колонкам.
- Графики — папка `ui/charts/` (см. следующий раздел).

Состояния: `EmptyDataState`, `ErrorDataState`, `AsyncDataView` — если нужны вне карточек.

Поведение любого блока можно сначала проверить в Storybook (npm run storybook)

## Числа и подписи

Вся логика в `ui-kit/visualization`. В экране **не пишите свои** `toLocaleString` / «млн ₽» вручную.

Все подписи идут через `formatByMetric(value, format, options)`. Локаль `ru-RU`. `null` везде рисуется как «—».

| Формат | Что получает | Как выглядит |
| --- | --- | --- |
| `text` | строка (число — как `number`) | «Финансы» |
| `number` | число | до 2 знаков: `1 234,5` |
| `percent` | доля от 0 до 1 | `0.083` → `8,3 %` |
| `currency` | сумма | полная, без копеек: `12 000 000 ₽` |
| `currencyCompact` | сумма | `1,4 млрд ₽`, `12 млн ₽`, `850 тыс. ₽`; меньше тысячи — как полная сумма |

Валюта — `RUB` (по умолчанию), `USD` или `EUR`: `formatByMetric(value, format, { currency: 'USD' })`. Её можно задать в KPI (`currency`) и в колонке таблицы (`currency` при `format: 'currency' | 'currencyCompact'`).

Пороги сокращения одни: 1 000, 1 000 000, 1 000 000 000. Миллионы и миллиарды — одна цифра после запятой, тысячи — целое.

Где какой формат уже подставлен:

- **KPI.** При `unit="currency"` карточка сама вызывает `formatCurrencyKpi`: миллионы и миллиарды сокращаются, тысячи и меньше остаются полной суммой (`1 371 877 259 ₽` → `1,4 млрд ₽`). `percent` и `number` идут через `formatByMetric`. Дельта в процентах — тоже доля 0…1. На карточке: `currency="USD"` при `unit="currency"`.
- **Таблица.** Формат колонки (`format`) и при необходимости `currency`. Числовые форматы получают класс с ровными цифрами (`metricDisplayClass` → `tabular-nums`), чтобы колонки не прыгали.
- **График, ось.** Один масштаб на всю ось — по максимальному модулю значений (`resolveChartValueScale` / `formatChartAxisTick`). Если максимум в миллиардах, все тики в «млрд», даже маленькие. У тика размерность рядом с числом (`12 млн`), отдельной подписи оси нет. Для рублей меньше тысячи тик — целое с `₽`. Для процентов ось умножает долю на 100.
- **График, тултип.** То же `valueFormat`, но уже полным `formatByMetric`: для `currency` и `currencyCompact` со знаком валюты.

## Какой график выбрать

Импорт нужного компонента — из `@ui-kit/components/ui/index.ts` (блок `charts`).

График кладётся внутрь `ChartCard`. Данные готовит экран: массив объектов или шаги. Компонент только рисует.

| Ваша задача | Компонент |
| --- | --- |
| Тренд во времени (месяцы, недели), несколько серий | `LineTimeSeriesChart` |
| Сравнить немного категорий на одном периоде | `VerticalBarChart` |
| ТОП-N, длинные названия слева | `HorizontalBarChart` |
| Доля статей внутри одного столбца | `HorizontalStackedBarChart` |
| План и факт по статьям, длинные подписи | `HorizontalGroupedBarChart` |
| Структура в процентах | `PieChart` |
| Вклад статей в итог ± | `WaterfallChart` |
| Столбцы + линия плана/лимита | `ComboBarLineChart` |
| Детализированные данные | `DataTable` |

**Практические правила**

- Нет временной оси и мало категорий — столбцы, не линия.
- Много категорий для pie chart — таблица или столбец.
- На линейном графике легенда под графиком; много серий — прокрутка внутри карточки.

**Общие настройки** у столбцов, линии, combo и waterfall:

- `height` — высота области графика. Ширину задаёт класс сетки на `ChartCard`, не график.
- `valueFormat` — формат оси и тултипа. У grouped, stacked, combo и waterfall по умолчанию `currencyCompact`; у линии и простого столбца — `number`.
- `withTooltip` — тултип включён по умолчанию.
- `legend` — клик по пункту прячет серию. Если передать `onLegendToggle`, скрытие остаётся на экране, kit сам состояние не меняет.
- Цвет серии необязателен. Без него берётся палитра `--chart-blue`, `--chart-green`, `--chart-orange`, `--chart-purple`, `--chart-teal` по кругу.

**Как передавать данные**

- **`LineTimeSeriesChart`** — динамика. `data`, поле оси `xKey`, массив `series` (`key`, `name`, опционально `color`).
- **`VerticalBarChart` / `HorizontalBarChart`** — одно значение на категорию: `categoryKey`, `valueKey`, подпись `name`, цвет. Горизонтальный вариант без легенды; длинные подписи регулируются `categoryAxisWidth`.
- **`HorizontalGroupedBarChart` / `VerticalGroupedBarChart`** — несколько столбцов рядом. Те же `data` и `categoryKey`, плюс `series`. Горизонтальный — план/факт с длинными названиями.
- **`HorizontalStackedBarChart` / `VerticalStackedBarChart`** — доли в одном столбце, тот же вид `series`.
- **`ComboBarLineChart`** — столбец и линия: `xKey`, объекты `bar` и `line` (`key`, `name`, `color`). Без цвета столбец — факт (`--chart-blue`), линия — план (`--text-muted`).
- **`PieChart`** — `slices`: `id`, `label`, `value`, опционально `color`. В легенде рядом с названием доля.
- **`WaterfallChart`** — цепочка `steps`: `label`, `value`, `kind` (`start` | `delta` | `total`). Старт и итог одним цветом серии, прирост зелёный, снижение красный.

У **line** и **combo** графиков есть один уровень детализации: проп `drilldown`. В нём `drillKey` (поле вроде месяца `YYYY-MM`) и `getDetailData(drillValue, row)`, которая возвращает новый массив точек. Клик по точке оси подменяет данные, сверху появляется «Назад». Второй уровень вложенности kit не делает.

## Данные и логика

- Подготовку данных (фильтры, агрегаты) держите в `hooks` и `utils` папки дашборда, как в `dashboard/utils/`.
- Компоненты kit только **отображают** переданные массивы и числа.
- Цифры на экране должны совпадать с источником; если данных нет — пустые состояния kit, а не выдуманные KPI.

## Если нужного блока нет

Сначала добавьте компонент в `ui-kit` и story в Storybook, затем используйте на экране. Не дублируйте kit локальной вёрсткой в папке дашборда.
